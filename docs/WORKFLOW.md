# m2m 协作流程

最后核对：2026-09-13

这份文档写给所有参与 m2m 的人，不管你是改代码、改文案还是改设计，也不管你用不用 AI 工具。全程用 VS Code 的图形界面，不需要记命令。

只要记住一句话：**不要直接改 main。改动放在自己的分支上，开一个 PR，维护者合并。**

---

## 一、第一次准备（一次性，30 分钟）

1. **装两个软件**：[VS Code](https://code.visualstudio.com) 和 [Git](https://git-scm.com/downloads)。Git 安装时一路默认就行。
2. **注册 GitHub 账号**，把用户名发给维护者。收到仓库邀请邮件后点接受。
3. **把仓库下载到电脑**：打开 VS Code → 按 `Ctrl+Shift+P`（Mac 是 `Cmd+Shift+P`）→ 输入 `Git: Clone` → 粘贴仓库地址 `https://github.com/owliwik/m2m-prototype` → 选一个文件夹存放 → 打开。第一次会让你登录 GitHub，按提示登录。
4. **装一个扩展**（推荐）：左侧扩展图标 → 搜 `GitHub Pull Requests` → 安装。之后可以在 VS Code 里直接开 PR。
5. **只有改代码的人才需要**：装 [Node.js](https://nodejs.org)（选 LTS 版本）。然后在 VS Code 里 `Terminal → New Terminal`，输入 `npm install`，等它跑完；以后输入 `npm run dev` 就能在浏览器打开 `http://localhost:3000` 看到网站。另外找维护者要一份 `.env.local` 文件放在仓库根目录，不要从别的地方复制。
   只改文字、文档、设计稿的人跳过这一步——你可以直接在 PR 的预览链接里看效果（见下面第 7 步）。

---

## 二、每次改东西的流程

1. **先更新到最新**：VS Code 左下角显示当前分支名，点它 → 选 `main`。然后左侧「源代码管理」面板（Source Control，图标是三个圆点连线）→ 点面板上方的同步 / 拉取按钮（或 `...` → `Pull`）。
2. **新建自己的分支**：再点左下角分支名 → `Create new branch...` → 起名 `你的名字-做什么`，比如 `xiaoming-landing-text`、`lily-duke-page`。用英文或拼音，短一点就行。
3. **改东西**，正常保存。
4. **提交**：回到「源代码管理」面板，会看到你改过的文件。在上方输入框写一句话说明改了什么（比如「修改首页文案」），点 `Commit`。如果它问要不要暂存所有改动，选「是」。
5. **推送**：点 `Publish Branch`（第一次）或 `Sync Changes`（之后）。
6. **开 PR**：VS Code 会弹出 `Create Pull Request`，点它；或者打开 [GitHub 仓库页面](https://github.com/owliwik/m2m-prototype)，会看到黄色横幅 `Compare & pull request`。标题写清楚改了什么，正文简单说明去哪里看效果。
7. **看预览**：等一两分钟，Vercel 机器人会在 PR 下面贴一个预览链接。点开，检查你的改动对不对。这就是你的改动上线后的样子，不需要在自己电脑上运行网站。
8. **在群里说一声**「PR 开好了」。维护者检查后合并，网站自动更新。
9. 合并之后，回到第 1 步（切回 `main`、拉取最新）。旧分支不用管，维护者会清理。

一件事一个分支。做完就开 PR，别攒着——改动越小，越好检查，越不容易冲突。

---

## 三、就这几条规矩

- **不直接改 main。** 这是唯一的硬规矩。
- **提交说明写人话。** 「修改首页文案」「加了 Duke 学校页」「修复登录按钮错位」。
- **密钥不进仓库，也不进聊天。** `.env.local`、密码、任何 key，一律找维护者私下要。
- **不确定就问。** 出现红字、合并冲突、看不懂的提示——截图发群，维护者处理。不要自己猜着点。
- **开始前先拉取最新**（第二部分第 1 步）。这一步能避免绝大多数冲突。

---

## 四、看进度、领任务

`docs/STATUS.md` 是我们的任务板：现在做到哪、谁在做什么、接下来做什么。由维护者更新。想领什么任务，群里说一声就行。

---

## 五、用 AI 工具（可选，不用也完全没问题）

如果你用 Claude Code、Cursor、Copilot 这类工具，开始前让它先读仓库根目录的 `CLAUDE.md`——里面是项目的技术说明和约定。其余流程和上面一样：分支、提交、PR。

不用 AI 工具的人，这一节可以忽略。

---

## 六、维护者要做的事（其他人不用看）

- 合并前确认 Vercel 预览构建成功（等于跑了 lint 和 build）；有必要时本地再跑 `npm run lint` 和 `npm run build`。
- 合并前更新 `docs/STATUS.md`，有决策就记进 `docs/DECISIONS.md`，`CLAUDE.md` 里过期的地方顺手改掉（Claude Code 里输 `/wrap-up` 可以自动做）。
- 数据库改动（schema、RLS、枚举）只由维护者做，SQL 先放进 `docs/sql/` 再执行，规则见 `CLAUDE.md`。
- Vercel 的 Preview 环境要配好和生产一样的环境变量，否则大家看不到预览。
- GitHub 上给 `main` 开分支保护（必须走 PR），并开启「合并后自动删除分支」。
- 定期把 `.env.local` 的最新版本私下发给需要本地运行的人。
